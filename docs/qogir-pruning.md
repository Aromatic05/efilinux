# Qogir runtime pruning

EFI Linux uses Qogir as the default XFCE icon and cursor theme, but the upstream
installation is a distribution-wide catalogue rather than a runtime closure for
this image. The unpruned tree contains icons for thousands of applications that
are not installed, multiple fixed-size copies of the same semantic icon, and
large compatibility alias sets for unrelated desktops.

The pruning process is deterministic and runs inside the `qogir-icon-theme`
recipe after the upstream installer has produced its single standard-color
variant. It is not a post-build deletion pass over the assembled image.

## Measured baseline

The 2025-02-15 upstream Qogir tree in the current graphical image occupied about
124 MiB on the build filesystem. Its apparent payload was about 22.1 MB; the
larger allocated size was caused mainly by thousands of small SVG files and
symbolic links, each consuming filesystem metadata and blocks.

The initial retained runtime closure occupies about 38 MiB in the composed
rootfs and has an apparent payload of about 11.3 MB. This is an approximately
69% reduction in rootfs allocation and 49% reduction in apparent content size.
Temporary copies can report different allocated sizes on copy-on-write or
compressed filesystems, so regression tests use apparent bytes and entry count.
The exact final EFI saving is measured separately during image composition.

## Ownership boundary

The immutable base theme owns only icons needed by GTK, XFCE, Thunar, core
network/audio/storage integration, generic MIME types, and maintenance tools.
Optional `.zxm` modules must install their application icons into `hicolor`.
Qogir inherits from `hicolor`, so a module never requires modification of the
base Qogir package.

This rule prevents the base image from reserving space for browsers, WPS,
recovery suites, or other software that is not currently loaded.

## Retained classes

The cursor theme is retained in full because cursor lookup uses a broad alias
set and missing aliases produce visible fallback regressions.

The base also retains:

- scalable and symbolic MIME icons for arbitrary user files;
- storage, removable-media, input, network, audio and power device icons;
- places such as home, desktop, folders, network locations and trash;
- generic status, emblem, category and notification icons;
- a filtered set of GTK/XFCE/Thunar actions;
- a filtered set of installed application icons;
- a filtered XFCE panel and notification-area set;
- small fixed-size application icons needed by menus plus scalable versions.

The allowlists describe semantic icon families. The pruning program follows
symbolic links one link at a time and automatically retains every intermediate
link and final target. A selected icon can therefore refer across size or
context directories without becoming broken.

## Removed classes

The recipe removes:

- brand icons for software absent from the base image;
- Wine, Steam, game, IDE, cloud-service and unrelated distribution aliases;
- most fixed-size duplicates where a scalable or symbolic form remains;
- panel icons for absent third-party tray applications;
- unused weather-size and high-resolution compatibility trees;
- upstream-generated `icon-theme.cache`, which the EFI Linux composer rebuilds
  after all packages have been merged.

It does not prune by arbitrary byte target. Every retained directory is declared
in the rewritten `index.theme`, and every declared directory must remain
non-empty.

## Validation contract

The permanent test verifies:

1. every symbolic link remains inside the theme and resolves;
2. every icon referenced by an installed desktop entry resolves through Qogir,
   hicolor or pixmaps;
3. representative XFCE, storage, MIME, action, status and cursor assets exist;
4. representative SVG assets can be decoded by the target GdkPixbuf loader;
5. allocated size and total entry count remain below explicit regression limits;
6. the icon cache is generated by the composer rather than shipped stale by the
   package.

A future application package changes its own hicolor payload, not the Qogir
allowlist. The allowlist should only be expanded when a base desktop component
uses a semantic icon that cannot be satisfied by the retained generic set.
